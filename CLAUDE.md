# HarmonicFitness: a workout podcast, made fresh each session

**Code introspection:** a codegraph index (`.codegraph/`, git-ignored) covers the engine; use the codegraph MCP tool (`codegraph_explore`) to find and read code, its callers and what a change touches, before grepping or reading files. After moving or renaming files, run `codegraph init` again to refresh it.

HarmonicFitness turns a request for a workout into a narrated MP3 for earbuds, with no screen and no timer. The audio is the workout: it tells the listener what to do, keeps them company, and moves them along on time. The lint predicts each segment's spoken length for the chosen coach; the render lays segments on the plan's clock, and a segment with time to spare widens its paragraph breaks, then ends early rather than going quiet, unless a `[hold]` keeps it its full length for timed work. Only the total is held to plan, within three percent either way: a natural voice matters more than exact timing.

Priorities, in order: safe for the listener's body today, clean to the ear, worth listening to.

## What runs when

- **Any request for a workout, in any words,** runs the `workout` skill (`.claude/skills/workout/SKILL.md`): check-in (asked first, from the profile, health and log alone), research, the brief, design, script, build, log and backup. `./harmonicfitness brief` supplies the ingredients, the writer designs and writes the session, and the build refuses any movement the brief's menu doesn't hold.
- **Getting started** ("set up harmonicfitness", "set me up", "finish setting me up"), **or changing the profile, injuries, feeds, audio route or delivery,** runs the `setup` skill (`.claude/skills/setup/SKILL.md`), as does a workout request when `me/profile.md` doesn't exist yet. Its quick start asks one round of questions, adds one web key where local voices don't run (`keys init`, then `keys open`), has them choose a coach by ear (locally, one of the ten stock local coaches from its style and 45-second `sample.mp3`; else the keyed service's stock web coach, made then with `./harmonicfitness coaches make`), and ends with a ten-minute workout. The rest of the interview waits for "finish setting me up" (`setup = "quick"` in `me/settings.toml` until then).
- **"I want a new coach", in any words, at any point,** runs the `coach` skill (`.claude/skills/coach/SKILL.md`): "switch coach" picks another of the ten stock local coaches by ear; a coach of their own is a web coach: keys, describe (a narrative file), audition across every keyed service, approve and name, the stable; the quick coach is one question, then that audition. Local coaches are chosen, never made, since 0.15.0.
- **A request from outside a copy of this repo** ("use https://github.com/RNCDev/harmonicfitness and set me up") follows the README's "For Claude" section: download to `~/harmonicfitness` (git or the ZIP; no GitHub account needed), then hand over to a session opened in that folder, where these instructions and the safety settings load. A new listener is set up only on their own computer, never on Claude Code on the web; one already set up, with their private context repo attached, keeps working there with web coaches. Keep that section, the README's Start here and the setup skill in step.

Rules that always hold:
- **Never read, print or copy `me/.env`**: it holds the listener's voice keys, pasted into that file by the listener, never into the chat. Only the engine reads it, when it sends to a voice service.
- **During a session, write only inside `me/`.** Never put personal details (health, location, the log, drafts) in the engine, its tests or its examples; the pre-push hook in `tools/hooks/` and CI both refuse them.

## Two assistants

HarmonicFitness runs under Claude Code and under ChatGPT's Codex (Codex in the ChatGPT desktop app, the Codex CLI or an editor), on the listener's own computer.
- **Claude Code's files are the source:** this file, `.claude/skills/` and `.claude/settings.json` (which allows `./harmonicfitness` and denies Claude's file reads of `me/.env`). Skills name Claude Code's tools.
- **Codex reads `AGENTS.md` and `.agents/skills/`,** both written by `./harmonicfitness harness sync` (`tools/harness.py`). `AGENTS.md` sends Codex here and says what to use in place of each Claude Code tool (a numbered question for AskUserQuestion, `./harmonicfitness show` for SendUserFile, research done in turn for background agents). `.agents/skills/<name>/` is an exact copy of `.claude/skills/<name>/`; the ChatGPT app's own import of Claude skills makes the same copy, so it changes nothing. **After editing a skill, run `./harmonicfitness harness sync`**; the tests fail until it's done.
- **`.codex/config.toml`** turns on the sandbox's network, and **`.codex/rules/harmonicfitness.rules`** lets `./harmonicfitness` run outside Codex's sandbox, as `.claude/settings.json` allows it here; Codex reads both once the listener trusts the folder. The harness check keeps that rule and the allow list naming the same command.
- **Without the rule** (an untrusted folder), Codex's sandbox hides the GPU, uv's home cache, git's settings and the network. So inside it (`CODEX_SANDBOX` set) `./harmonicfitness` keeps uv's cache in `.cache/uv` (git-ignored) and a local render that can't see the GPU says to run again outside the sandbox; and setup skips the privacy hook, with the reason, whenever git's settings can't be written.
- **The key:** Claude Code's settings deny its file tools `me/.env`, and both assistants are told never to read it (a shell command could). A system-level block in Codex (a permission profile denying `**/*.env`) also stops the engine reading it, so web coaches couldn't speak.
- Tried end to end on 2026-10-25 with the Codex CLI the ChatGPT app ships (0.164), on the Free plan's model: setup and a ten-minute workout with Coach Andy. The app's own trust prompt, multiple-choice questions and approval prompts weren't tried by hand.

## Three layers

1. **Engine** (this repo, public, versioned): `harmonicfitness`, `tools/`, `.claude/`, `AGENTS.md`, `.agents/`, `.codex/`, `tests/`, the shared knowledge in `knowledge/`, the template `me.example/`, and `docs/`.
2. **Coaches.** Each is a persona folder (a person's name, how they talk, how they sound; `knowledge/voices.md`), of one of two kinds: a **local coach** (`kind = "local"`), one of the ten the engine ships, spoken on this computer by Pocket TTS from its saved voice file, which renders only locally; or a **web coach** (`kind = "web"`), an original voice a web service designed from a description and saved in the listener's own account, which speaks only through that service. **The stock coaches** are part of the engine, in `coaches/` (public, versioned; `coaches/roster.toml` says how each local one was made, and `tools/coachmaker/` remakes them, maintainer only):
   - **Ten local coaches**, five men and five women (Andy, Marcus, Theo, Sam, Callum; Maya, Claire, Rosa, Helen, Kate): each folder holds `persona.md`, `clip.wav` and `clip.txt` (the designed voice it came from), `pocket.safetensors` (its Pocket voice state), `cues/` (recorded counts and cues), `pace.json` (measured from its sample) and `sample.mp3` (45 seconds, for choosing). Coach Andy is the local stand-in a build takes when no coach was ever chosen.
   - **Four stock web coaches** from one description, all `placeholder = true`: Coach Reed (Fish Audio), Coach Ellis (ElevenLabs), Coach Nolan (Gemini) and Coach Owen (Inworld), each `pending = "design"`: setup's quick start, or else the first build that needs one, designs and saves its voice in the listener's account, saying so first, and writes the made coach to `me/coaches/<slug>/`, which wins over the stock copy from then on.
   The listener's own coaches (web coaches) live in `me/coaches/`; a coach there wins over a stock coach of the same name.
   Local model weights never go in git: they download into `models/` (git-ignored, at pinned revisions).
3. **The listener's context** (private): `me/`, ignored by git, holds everything about one person; `me.example/` is its template. Set `HARMONICFITNESS_HOME` to keep it elsewhere. Every tool reads its paths from `tools/paths.py`, and reads and writes the context files only through `tools/context.py`. Each Markdown context file opens with a TOML block between `+++` lines naming its format (`schema = 6`) and holding the settings the tools read; `settings.toml` is plain TOML. The profile is four files, which `context.profile()` reads as one. `./harmonicfitness migrate` brings a folder from an older release up to date.

## The listener's files (`me/`)

- **The profile, in four files** by how often each part changes and who reads it. `context.profile()` merges their settings and joins their prose, so a setting counts in any of them, but each has a home (`SETTING_HOMES` in `tools/context.py`), where setup writes it and `migrate` moves it; the home file wins, and `check` notes a setting written twice.
  - `profile.md`, who the listener is (rarely changes; every workout reads it): `name` (what the coach calls them), `experience`; the Basics (neighborhood), Listening setup and other prose.
  - `training.md`, how they train (changes with new gear or check-in feedback; every workout reads it): `likes`, `dislikes`, `[[kits]]` (with optional `weights` and `unit`); the Default session section, and Equipment kits notes the settings can't hold.
  - `content.md`, what fills the rests (changes most; only research and the story tools read it): `youtube_favorites`, `puzzles`, `[[interests]]` (name, slot, detail), `[[feeds]]`; the Content (with "Never bring up") and Taste sections.
  - `settings.toml`, the tools' own settings (plain TOML, no prose; setup writes them): `setup` (`"quick"` until the second half of setup), `render` (the audio routes in order, default `["local"]`; a web coach always speaks through its own service and a local coach always renders locally, so it matters only with no coach to go by), `cloud_max_chars` (a web build's ceiling), `deliver_to` (a folder, or a list of them, one per computer), `words_per_minute` (a rough rate `./harmonicfitness get wpm` prints; builds use each coach's measured pace).
- `health.md`: injuries and limitations. Its `+++` block holds a `[[limits]]` row per injury (area, side, level `off-limits` or `delicate`, optional `flags` and `rehab`, note), which `./harmonicfitness brief` applies; the prose holds each injury's story and the `## Clinician rules`, followed literally. The check-in loosens or tightens a limit.
- `log.md`: the session log (added only with `./harmonicfitness log-session`, which checks every field) and the listener's feedback ("too long", "loved that topic") under Feedback.
- `workouts/`: one folder per workout, `<stem>/` (such as `2026-10-25-strength-25/`): the `@@`-marked draft (`<stem>.draft.txt`), the brief it was designed from (`<stem>.brief.md`), the menu the build checks (`<stem>.menu.json`), and the build's `<name>.txt` and `<name>.build.json` (with the MP3 until it's delivered, or the web copy on the web). `checks/` holds smoke tests and builds of drafts outside a workout folder (`tools/workouts.py` decides). `research/` holds the filler: `daily/` (each day's research sheet and feeds), `videos/` (video deep-dive sheets and transcripts), `puzzles/`, `reserve/` (evergreen pieces researched ahead of time; `migrate` renames a `pantry/` from before 0.10.2) and `told.jsonl` (every filler item told). `.audio-cache/` holds rendered clips (`./harmonicfitness cache prune` clears old ones freely), and `.logs/` each build's render log (past 1 MB it starts over, the older lines kept once as `.log.1`; `cache prune --logs-older N` removes those older than N days) and `builds.jsonl`: one record per MP3, a `"failed": true` line for a web render that sent text and then stopped, and an outcome line (`"event": "stopped"` with the stage and why, or `"delivered"`) for each full build; every line of one build, and its log header, carry its `build_id`. Each line names its `kind` (`mp3`, `failed` or `outcome`; a line from before 0.19.0 is read by its fields, never rewritten), and every reader goes through `records.parse`, which skips a line whose fields have the wrong type.
- `coaches/<slug>/`: one folder per coach of the listener's own (`personas/` before 0.15.0; `migrate` renames it), named for the coach and where they speak (`coach-dana-fish`; a folder from before 0.10.3 keeps its name, and lookup by the plain `coach-dana` still finds it). `persona.md` (persona schema 5) has a `+++` block: `name`, `aliases`, `kind`, `placeholder`, `description`; a web coach's `service`, `voice_id`, optional `model`, `style` (kept empty: Gemini takes none yet), `made`, `pending = "design"` on an unmade stock coach, `[voice]` (who, sound, energy, pace, avoid: what services design from) and `[character]` (what the script writer follows); a stock local coach's `gender` and `[local] engine = "pocket"`. Below it, free notes; the brief quotes `[character]` and the prose's `- Label: text` lines. `pace.json` holds pace per engine or service, model and voice (a web coach's starts as an estimate from its sample) and each computer's render speed; a stock local coach's ships with it and is read until this computer's first render, which adds to it in the shared `me/workouts/.audio-cache/voice-pace.json`, so `me/coaches/` holds only the listener's own coaches (and a stock web coach once made in their account). A web coach adds `sample.mp3` (its approved candidate). `coaches/.auditions/<date>-<n>/` holds an audition in progress (each candidate's WAV and MP3, `narrative.md`, `candidates.json`); `coaches/.archive/` holds archived coaches, out of the list but found by name for old log lines (`migrate` moves a local coach of the listener's own there: they no longer render).
- `.env`: the web voice keys (`FISH_AUDIO_API_KEY`, `ELEVENLABS_API_KEY`, `GEMINI_API_KEY`, `INWORLD_API_KEY`), one `NAME=value` per line, made by `./harmonicfitness keys init <service>`, opened in the system's editor by `./harmonicfitness keys open`, filled in by the listener.
- `movements.toml` (optional): private `[[movement]]` entries in the catalog's format, loaded after the shipped ones (a shipped id wins).
- `.gitignore`: for keeping `me/` as its own private git repo, nested in the engine's folder and ignored by the engine's git (never a submodule). It leaves out `.env`, the clip cache, MP3s (keeping each web coach's `sample.mp3` and a workout's web copy), render logs and auditions in progress. `./harmonicfitness backup` commits and pushes that repo, and refuses to commit a `.env` even if the rule is missing.

## Knowledge (`knowledge/`)

- `movements.toml`: the movement catalog. Each movement's equipment, patterns, muscles, how much it loads each joint area (`loads` 0 to 3, and `support` for the resting side), flags, intensity, level, `effort` (easy, moderate or hard, on every conditioning movement), timing, spoken setup and cues, and the coaching a listener without a mirror needs (`rep`, `feel`, `faults`); also the fixed lists of equipment, patterns, muscles, areas and flags, the kit presets, `[limit_cues]` (spoken cues per area and limit level), and `[unlisted]` (real movements it doesn't hold, which the build refuses in a script). Read only through `tools/catalog.py`.
- `sessions.toml`: the session methods (goals, length, levels, how warm-up, work, finisher and cool-down share the time, the patterns that fill each block), the doses per intensity and level, the all-out sprint rule (`[all_out]`: rest at least four times the work), the caps on hard sets and efforts per session, and the bodyweight reps above novice; every number marked as sourced or a house default. Read only through `tools/sessions.py`.
- `programming.md`: how to set effort, rest, tempo and progression, and how the check-in's readiness changes the day, with sources; `sessions.toml` takes its numbers from it.
- `injury-playbook.md`, `kits.md`: what off-limits and delicate mean for each area, the signs that let a limit loosen, and the red flags that stop a session; what each kit usually holds and how to script around it. Where they disagree with `me/health.md`, the strictest wins.
- `script.md`: what goes in a script, from the welcome to the sign-off (the `movements:` line and segments, timed work, the opening and its safety rules, coaching from the notes and limit cues, the self-check that adjusts each main movement, filler, the quiz and deep dive, the close). `tts-rules.md`: how to write for text-to-speech, and how the coach should sound.
- `content.toml`: the filler plan: the slots (today, science, deep dive, quiz, delight, learn), how many a session carries by length, the reserve's target per evergreen slot, the default categories. Read only through `tools/content.py`.
- `voices.md`: the two kinds of coach and the stand-ins, how a web coach is made, the web services with their costs, terms and what goes to them, the stock coaches, the local engine (Pocket TTS) by computer and how the ten were made, counts and cues, pace, and what was tried. `services.toml`: the one list of web services, in order (a route is `local` or one of them; `cloud.SERVICES` and `cloud.ROUTES`, from which `routes`, `keys`, `coaches` and `context` take theirs): each one's address, key name and the page to get a key, default model, rates (with the date checked), `design_usd` where published, concurrency, request limit, `candidates` per audition, `note` and `tried_live`; read only through `tools/cloud.py`. A new service is a section here and a module in `tools/services/`.
- `research/`: the evidence behind the knowledge files, one dated note per question (training, biomechanics, exercises, equipment), each citing only sources opened and ending with what wasn't confirmed; its README indexes the notes and what each feeds. No tool reads it.
- `smoke-test.draft.txt`: a one-minute check that also measures a local coach's pace on a route.

## Tools

Every tool runs through `./harmonicfitness <command>` (`tools/harmonicfitness.py` dispatches; `./harmonicfitness help` lists the commands, and each Python tool takes `--help`; `setup` and `doctor` are shell scripts the `./harmonicfitness` wrapper runs before any environment exists, sharing `tools/common.sh`), in the project's environment (`.venv`, Python 3.11), or under `HARMONICFITNESS_PYTHON` if set; the Mac's own `python3` is never used. Skills and docs call tools only this way, so one permission rule covers them. Exit codes (`tools/cli.py`): 0 done; 1 issues to fix; 2 the total ran more than three percent off plan; 3 a local coach isn't measured on this route yet; 4 a web service refused the key, payment or quota; 64 the command was wrong (an unknown or retired command or option, an unknown coach, a missing draft) or a web coach can't speak here (no key for its service on this computer, or `--route` naming another service; a build name a file can't take); 70 a bug in the engine (`cli.BUG`: nothing to fix in the draft or the command; its traceback, keys taken out, on stderr); 130 interrupted (Ctrl-C; "Interrupted." on stderr). Every numeric option takes its value through `cli.positive_int`, `non_negative_int`, `positive_float` or `non_negative_float`, so `--minutes 0` is 64 on every command (`test_contract` walks the parsers to hold it). A build's name passes `workouts.safe_name` (no `< > : " / \ | ? *`, control character, trailing dot or space, or Windows device name such as `con`), on every computer alike. Every tool's `main` runs through `cli.run`, which maps what it raises to those codes (`cli.Usage`, argparse's and a `main`'s refusal, to 64; an exception carrying `exit_code` to its code, such as `errors.UsageError`'s 64 for an unknown coach (`personas.UnknownCoach`) or a web coach that can't speak here (`routes.WebCoachUnavailable`); any other exception to 70 with its traceback, keys taken out, on stderr; every message it prints has the keys taken out too, and with `HARMONICFITNESS_DEBUG` set a reported problem's message is followed by its scrubbed traceback), so the codes hold from every entry point. A report goes to stdout and the line saying why a command failed to stderr; `--json` on `coaches list`, `content plan`, `coverage` and `get` prints the same facts as one JSON object, its keys in its `--help`. `--date` is a day on record (`log-session`, `content log`), `--today` only "pretend today is" (`brief`, `content plan`); `test_contract` walks the parsers to hold both. Library code never exits: it raises one of `tools/errors.py`'s typed errors (`HarmonicFitnessError`, exit 1 unless it says otherwise; `UsageError` (64), `ContextError`, `LogRefused`, `CoachError`, `RouteUnavailable`, `EngineError`, `DraftError`, `RenderStopped`, `MigrateError`), or `cloud.ServiceError` or `screen.Unfit`; a caller that carries on past a problem catches the kind it means, or `errors.PROBLEMS`. The exit codes live in `tools/errors.py` (cli re-exports them), so a module with no `main` never imports `cli`. `tests/test_contract.py` keeps `SystemExit` and `cli` out of library code and pins the codes. `tools/fileio.py`'s `atomic_write` is how every record, menu and context file is written: to a temporary file beside it, then renamed; `fileio.replace` renames over a file (retrying on Windows while another program has it open), `atomic_copy` copies the same way, `read_jsonl` is the one JSONL reader, and `append_jsonl` adds to `builds.jsonl` and `told.jsonl` under the file's lock (`locks.file_lock`), sealing a line a crash left torn; `read_json(path, shape)` reads a JSON file (the build record, a menu, `.claude/settings.json`), raising `ContextError` naming the file when it's damaged or the wrong shape (a missing one is the caller's to answer).

**Setup and the computer**
- `tools/doctor.sh` (`doctor`): the readiness check, a shell script so it runs before the environment exists: the system, chip, graphics, memory and free disk; uv, git, ffmpeg and the environment; whether local voices work here and, if not, why; then `tools/doctor.py`'s lines (the models on disk, `me/` and its schema, each `deliver_to` folder, ffmpeg's MP3 and loudness abilities). `--facts` prints `key=value` lines that `tools/machine.py`'s `facts()` reads (a library: `routes` and `doctor` take the computer's facts from it, as `hub_dir` the models folder), so the shell script alone decides what a computer can do; `HARMONICFITNESS_FAKE_*` variables stand in for the hardware in tests. On Claude Code on the web (`CLAUDE_CODE_REMOTE=true`) local voices are off, and `doctor.py` adds what the web needs: the key as an environment setting, the hosts to allow, and whether the context folder is kept. The web client's worker sets `HARMONICFITNESS_WEB=1`: no local voice, keys added in the app, the MP3 kept for the app to upload.
- `tools/setup.sh` (`setup`): one-time setup, safe to rerun: the readiness check, uv (`--install-uv` runs Astral's installer), the environment (`uv sync`), `me/` from `me.example/` (or a migration of an existing one, adding its `.gitignore` if missing), the privacy hook (skipped, with the reason, outside a git checkout, where git's settings can't be written, or where git already takes its hooks from elsewhere), and where local voices run, the local engine (an optional uv extra, Pocket TTS on PyTorch with the take checker: `cpu` on an Apple Silicon Mac or a PC's processor, `cuda` with an NVIDIA card, remembered in `.venv/.harmonicfitness-extra`; an `mlx` marker from before 0.15.0 becomes `cpu`) and its model and the take checker (`coaches download`). `--local` insists, `--no-models` stops at the base environment; a profile whose `render` list leaves out local (read through `./harmonicfitness get routes` on a rerun) gets no engine. `tools/common.sh` holds what it shares with `doctor.sh` and the wrapper: where uv and the environment's Python are, how uv installs, whether this is a git checkout.
- `tools/models.py` (`models`): the models in `models/` (and those older versions downloaded that nothing uses now, to delete), and `adopt` from Hugging Face's usual cache. `tools/voices.py`: the local model's pins (`LOCAL_MODELS`, `POCKET_FILES`: each file the language config loads at its own revision, `POCKET_LANGUAGE`, `CHECK_MODEL`), pace and render speed per coach, and downloads. `tools/ffmpeg.py` finds ffmpeg (PATH, else imageio-ffmpeg's copy) and runs it: every call goes through `run` or `to_mp3`, with a timeout (the workout's encode gets twice its length, at least two minutes), and a failure or a hang is a `RenderStopped` naming ffmpeg's version, exit code and last words. `tools/paths.py`: where everything lives (the context folder from `HARMONICFITNESS_HOME`, else `me/`, else on Claude Code on the web the one folder beside the engine holding a profile and `coaches/` or `personas/`; `SHIPPED` is the stock coaches' `coaches/`, which the tests point at a fixture with `HARMONICFITNESS_SHIPPED`). `tools/harness.py` (`harness`, `sync`): Two assistants, above.

**Building a workout**
- `tools/build.py` (`build <draft> "<name>"`): draft to `.txt` and `.mp3` in one process: the draft is read once, and the lint, the menu check and the render all see that text; the MP3 goes into the draft's workout folder (else `checks/`), then a copy to the profile's `deliver_to` folder, after which the local MP3 is removed (a failed copy or no folder keeps it; the build record says which, under `delivered_to`, `kept_local` and `reason`). `build.main` only parses: `run_build(BuildOptions)` is the build (`resolve_voice`, `gate`, `render_and_deliver`, and the pure `delivery_plan(remote, web, folders, client=False)`, which with `client=True`, the web client, keeps the MP3 for the app to upload), returning a `BuildResult` (code, record, lines), and runs under one stage, so any stop of a full build (not `--lint-only`, `--follow` or `--clips-only`) leaves exactly one outcome line in `builds.jsonl`: `stopped` (with its stage: coach, pace, lint, menu, design, render, drift, web-copy, deliver), `measured` (the smoke test) or `delivered`. The render's chatter goes to `me/workouts/.logs/<name>.log` (the standard error descriptor is pointed there for the render and a pending coach's design, and the engine's own printed lines go there too; `--verbose` leaves the chatter on the terminal), appended with a dated line naming the build's `build_id`, with a bug's traceback (keys taken out) or a stop's reason; its last lines print on a failed render. A failed copy keeps its reason (a full disk, a permission) in the record. A model that won't load says whether it was the network, memory, or what else (`engines.load_error`). Past 2 GB of clips, a build mentions `./harmonicfitness cache prune` (the cache is never pruned on its own: a web coach's clips are paid for).
  - Every draft but the smoke test (`knowledge/smoke-test.draft.txt`, known by its place, never by its name) needs the menu `brief --save` wrote beside it (`<stem>.menu.json`), from today and from `me/health.md` as it stands: the build stops on a movement that isn't on it, a menu from another day, or one made before health.md changed (`menu.gate`; `--lint-only` only warns about the last two). The gate also checks the menu's shape (`menu.validate`) and, on a full build, screens the menu's request again against today's health.md (`menu.rescreen`), refusing a movement (or a side) the screen no longer allows: the request can tighten health.md's limits, never loosen them. The build is the only way to lint or render a draft: the `lint` and `render` commands were retired in 0.14.0, and the dispatcher answers either with the `build` that replaces it (exit 64).
  - `--coach` names the coach (default the one used last, else the listener's own, else a stand-in that can speak here: a stock web coach with a key, then Coach Andy, except in web mode (`HARMONICFITNESS_WEB=1`), which never falls back to a local stand-in; it stops when the one used last is archived) and `--route` (or its older name, `--engine`) the route; the build resolves both once, for the lint and the render alike. A `pending` default web coach is made first (`coaches make`), except with `--lint-only`. An unknown flag exits 64 before anything runs or costs money.
  - `--lint-only` stops after the lint. `--follow` renders ahead while a draft is being written, keeping the model loaded and rendering each new or edited paragraph as it lands, and steps aside when the full build starts; `--clips-only` renders what the draft holds once; both are local only (refused for a web coach, where each re-render is billed). `--allow-estimated` renders with a local coach not yet measured on the route.
  - `--web` (on by default on Claude Code on the web, where it replaces the copy) makes the web copy with `tools/webcopy.py`: the MP3 mono at 48 kbps in parts of at most 14 MB (`<name>.web-1.mp3`...) and `<name>.player.html`, which plays them in order; the workout skill publishes it as an artifact and the backup commits it. The web client's worker sets `HARMONICFITNESS_WEB=1`: no local voice, keys added in the app, the MP3 kept for the app to upload.
- The lint refuses an ellipsis in spoken text: tested on Chatterbox Turbo (HarmonicFitness 0.14), a countdown written "Three... two... one... and rest." lost "and rest" in three takes of five, and with commas nothing in ten.
- `tools/draft.py`: the draft format (the `movements:` line, never spoken, then `@@ <seconds> | <label>` segments, `[pause]`, `[chime]`, `[hold]`, and `[count 5 go]` and `[cue rest]`, a coach's recorded counts and cues on a one-second beat), where a draft's brief and menu sit, and the timing layout the lint and the render share. `tools/counts.py`: a coach's recorded counts and cues (`cues/` beside its clip, with `cues.toml`): each clip's exact length for the lint and its audio for the render. A coach without recorded counts (a web coach) says the same count in words, as one line (`counts.in_words`), so one draft works with every coach; with a coach that has them, the lint refuses a countdown written in words. The brief's Counts line says which. `tools/tts_build.py`: the lint and `.txt` export the build calls; it stops on what must hold (text a voice can read cleanly, paragraphs short enough for one clip, the total within three percent), and shows segments far off their slots and each held segment's spare silence. `tools/menu.py`: the menu file (the request, the day, a hash of `health.md`, every movement allowed) and the check behind `menu.gate` (a declared movement off the menu, a catalog movement named in the text that's off it, nothing declared, segments that don't add up, a menu from another day or from before health.md changed; a menu movement named but not declared is a warning). The text scan reads every name and alias, longest first, except the everyday coaching words in `menu.EVERYDAY` (one-word aliases such as squat, swing or plank); a shortened name counts as the declared movement only when it names no other movement; a negation ("no", "not", "skip", "instead of", "like"...) excuses a mention only right before it, in its own clause, with only small filler words between ("not doing the jumping jacks"; "no rest between jumping jacks" still counts). The catalog's `[unlisted]` names (`catalog.Catalog.unlisted`: real movements it doesn't hold, such as "pistol squat", "walking lunge" or a bare "lunges"; never a name or alias of an entry, which the load refuses) are refused wherever the text says them, except as a shortened name of a declared movement ("lunges" after a reverse lunge). A movement the menu allows on one side only keeps to that side, segment by segment (`menu.side_problems`, which the web's plan check shares): a sentence naming it may hold no both-sides phrase (`menu.BOTH_SIDES`: "each side", "alternating"...) and no other side's word, and its segment no switch phrase anywhere ("switch", "other side", "other leg", "swap sides", "repeat on the other"); a negation doesn't excuse it. `catalog.resolve` is the one matcher for a spoken, declared or logged name (a leading side word dropped, a plural forgiven, a hyphen or a space alike).
- `tools/render.py` (`build` calls `render.run`, `render.clips` and `render.follow` in its own process): voices each paragraph, with the clip cache, the take check, each clip leveled to one speech level, a gentle compressor and the loudness pass, chimes and end tone, and a record of each build; it checks ffmpeg and the output's extension before a clip is rendered (or billed), and a web render that sent text and then failed leaves a `failed` line in `builds.jsonl`. One render at a time: `locks.render_lock` (`tools/locks.py`, flock on a Mac and msvcrt on Windows, shared with the pace file and with `cache prune`). `tools/engines.py`: the local engine (Pocket TTS) and the take checker's recognizer, and everything that depends on pocket_tts's, PyTorch's or onnx_asr's internals. `tools/counts.py`: a coach's recorded counts and cues. `tools/cache.py` (`cache`): the clip cache's size, and `prune` (a clip's verdict goes with it; `--logs-older N` removes render logs older than N days, alone pruning no clips, and never touches `builds.jsonl` or `told.jsonl`).
  - `render.py` keeps the orchestration (`run`, `render_cloud`, the take check, `follow`) and the ffmpeg encode; `tools/audio.py` holds the sound itself as PCM (silence, leveling, the chime and end tone, `assemble`), `tools/clipcache.py` the clip cache and each take's verdict, `tools/records.py` `builds.jsonl` (written and read: `log-session` and `get web-builds` read it, through `latest_build` and `is_mp3`, which skip outcome lines); `run` adds each stage's `timings` (render, check, assemble, encode) to the record, and `tools/wav.py` the one WAV writer. `render` re-exports their names.
- **The take check** (`render.check_takes`, `tools/verify.py`): a local build has a speech recognizer (`engines.listener`, Parakeet TDT 0.6B v3 through ONNX on the processor, `voices.CHECK_MODEL`, 2.5 GB in `models/parakeet-tdt-0.6b-v3-onnx/`, the same on every computer) hear every clip not checked yet and scores it against its line: the words aligned (digits read as words, a compound split or joined forgiven), a cue word dropped or swapped (go, rest, switch, stop, left, right, a count: `verify.CUES`), and what the audio alone shows (far longer or shorter than the pace predicts, a silence over a second and a half inside, clipping). A take passes with every cue said, no audio problem and at most one word in twenty off; a failed one is rendered again with the next seeds, up to four takes, and the best is cached under the line's own key with its verdict beside it (`<hash>.check.json`, naming the checker, `verify.checker_id`), so a line is heard once, and again only when the checker changes. A line whose best take still drops a cue stops the build (exit 1), naming it and what was heard; an unclear one keeps its best take and is listed. `--no-check` skips it; a web coach isn't checked (every take is billed), and the build record says which (`check`). A count or cue (`[count 5 go]`) is a recorded clip, never rendered or checked. `--follow` and `--clips-only` render unchecked; the build checks their clips.
- `tools/player.py`: plays a take with the system's player; `show <file>` opens a file's folder with it selected (Finder or Explorer; on Linux, the folder), the fallback when an MP3 can't be sent into the chat.

- `tools/routes.py`: the routes (`local` and each service in `services.toml`), which work here (the readiness check's verdict and the installed engine; a key in `me/.env` or the environment), and which a build takes: a web coach's own service, a local coach `local`, and with neither the first route in the profile's `render` list that works. `tools/keys.py` (`keys`): which services have a key (never the key), `init`, and `open` (the file in the system's editor, never read).

A 429 asking to wait longer than two minutes is a quota (exit 4), never slept through; a design or a save is never retried after it was sent; a redirect is never followed, and a `HARMONICFITNESS_<SERVICE>_URL` override counts only at an https address or this computer. `redact.scrub` (`tools/redact.py`, a leaf module; `cloud.scrub` re-exports it) takes every key value out of anything the engine prints, and a key holding a stray character (a line break, a space) is refused by name (`keys.BadKey`, exit 4) before it's sent. `tools/char_weight.py`: OmniVoice's character-weight rule (Apache 2.0, vendored); every measured pace counts in it.

## Audio

`tools/render.py` voices each paragraph on the route the build picked.
- **A web coach** speaks through its own service with the listener's key, by the voice saved there (`tools/cloud.py`); no clip is sent. A web build sends once, at the end, a few requests at a time, after printing the characters and approximate cost and checking `cloud_max_chars`. Its pace starts as an estimate from its sample, so it needs no smoke test.
- **A local coach** speaks with Pocket TTS (Kyutai's `pocket-tts` 4.0.1, PyTorch, CC-BY 4.0) from its saved voice state (`pocket.safetensors`), through the public model `kyutai/pocket-tts-without-voice-cloning` with the `english_2026-10` language config; `engines.public_only` refuses Pocket's request for its gated cloning model, so a Hugging Face login never changes the voice, and no login is ever needed. It runs on the processor on an Apple Silicon Mac (about 0.15 times the length of the speech on an M5: a 30-minute workout in about five minutes) or a PC (about 0.43), or on an NVIDIA card (about 0.29 on an RTX 2080 Super); `HARMONICFITNESS_DEVICE` overrides. No Intel Mac (no PyTorch build). A local render holds a lock and a second one waits; `--follow` overlaps rendering with writing. In `models/`: about 0.6 GB for Pocket and 2.5 GB for the take checker; `./harmonicfitness models` names older models nothing uses now. Its counts and cues are the coach's recorded clips, placed on a one-second beat (`tools/counts.py`).
- Every engine returns `say(text, seed)` with 16-bit mono PCM at 24 kHz, so the cache, loudness pass, timing layout and build record don't know which spoke. The cache key holds a local coach's clip and voice file (`pocket.safetensors`), engine, model, settings and runtime (Pocket's version, language config, PyTorch's version and the device), or a web coach's identity (service, voice ID, model, style, settings), never a key or a name.
- On Windows, `./harmonicfitness` runs from Git Bash and the venv's Python is `.venv/Scripts/python.exe`. On Claude Code on the web only web coaches speak: the key is an environment variable in the cloud environment's settings (the tools read the environment before `me/.env`), and the service's host (`api.fish.audio`, `api.elevenlabs.io`, `generativelanguage.googleapis.com`, `api.inworld.ai`) goes on its network allowlist. The web client's worker sets `HARMONICFITNESS_WEB=1`: no local voice, keys added in the app, the MP3 kept for the app to upload.

## Releases

Versions follow Semantic Versioning in its 0.x form (HarmonicFitness is pre-1.0: the numbering restarted at 0.16.0, and every older release was renumbered the same way, old major X becoming 0.X; `CHANGELOG.md`'s 0.16.0 section has the table). Tracked in `VERSION`, `pyproject.toml` and `uv.lock` (the `harmonicfitness` package's version line), and `CHANGELOG.md`, tagged `vX.Y.Z` on GitHub (RNCDev/harmonicfitness). 1.0.0 waits until the maintainer calls it stable. The maintainer decides the level:
- **Minor (0.X.0):** a change that breaks how existing drafts, coaches, commands, exit codes or the `me/` layout work, so something has to be migrated, or a change as large as a new assistant to run under (0.11.0). Its CHANGELOG section says what to do under "For forks". A change to a context file's format raises `SCHEMA` in `tools/context.py` and adds a step to `tools/migrate.py`, so a fork migrates with one command (`./harmonicfitness migrate`, which `./harmonicfitness setup` also runs).
- **Patch (0.x.Y):** everything else: a new capability (an engine, a web voice service, a skill step, a tool option), fixes, tuning and doc corrections.

Listener content lives in `me/` and is never part of the engine's git. When a set of changes is finished and working, release it: a dated section in `CHANGELOG.md`, the version bumped, commit, tag (`git tag -a vX.Y.Z -m "..."`), push with tags, and a GitHub release (`gh release create vX.Y.Z --notes-file <that section>`). Ask before pushing if it's unclear whether the work is done.
