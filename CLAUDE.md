# sweatcast: a workout podcast, made fresh each session

sweatcast turns a request for a workout into a narrated MP3 for earbuds, with no screen and no timer. The audio is the workout: it tells the listener what to do, keeps them company, and moves them along on time. The lint predicts each segment's spoken length for the chosen voice, and the render lays segments on the plan's clock: a segment with time to spare breathes a little between paragraphs, then ends early rather than going quiet. Only the total is held to plan, within three percent either way; a natural, human voice matters more than exact timing.

Priorities, in order: safe for the listener's body today, clean to the ear, worth listening to.

**Any request for a workout, in any words, runs the `workout` skill** (`.claude/skills/workout/SKILL.md`). It covers check-in, plan, research, script, build and log. **A request to get started, "set me up", or to change the listener's profile, injuries, feeds, voice or delivery runs the `setup` skill** (`.claude/skills/setup/SKILL.md`), and so does a workout request when `me/profile.md` doesn't exist yet.

## Three layers

1. **Engine** (this repo, public, versioned): `tools/`, `.claude/skills/`, `tests/`, and the shared knowledge in `knowledge/`.
2. **Voices** (public, small): `voices/` holds each shipped voice's reference clip, transcript and settings, including the Hugging Face model and the revision it's pinned to. Model weights never go in git; `./sweatcast setup` downloads them.
3. **The listener's context** (private): `me/`, ignored by git, holds everything about one person. `me.example/` is its template. Set `SWEATCAST_HOME` to keep it elsewhere; every tool reads its paths from `tools/paths.py`, and reads and writes the context files only through `tools/context.py`. Each context file opens with a TOML block between `+++` lines naming its format (`schema = 2`); in `me/profile.md` that block also holds every setting a tool reads. A folder from an older release is brought up to date by `./sweatcast migrate`.

During a session, write only inside `me/`. Never put personal details (health, location, the log, drafts) in the engine, its tests or its examples; the pre-push hook in `tools/hooks/` and CI both refuse them.

## Files
- `me/profile.md`: stable facts about the listener. The `+++` block at the top holds the settings the tools read (voices with the default first, `deliver_to`, `words_per_minute`, `youtube_favorites`, `puzzles`, `[[feeds]]`); the prose below holds the rest (basics, equipment kits, interests, tone). Update it when something lasting changes.
- `me/health.md`: injuries and limitations, with the standing rules and phase for each. The check-in updates the phase.
- `me/log.md`: session log and the listener's feedback. Sessions are added with `./sweatcast log-session`, which checks every field; feedback given at any time ("too long", "loved that topic") goes under Feedback.
- `me/exercise-science.md`: facts verified during this listener's sessions, in the shared file's format.
- `me/workouts/`: deliverables. `drafts/` holds `@@`-marked drafts, `research/` holds filler fact sheets (`videos/` the video deep-dive sheets and transcripts, `puzzles/` the quiz puzzles used), `.audio-cache/` holds rendered clips and each voice's measured pace (`voice-pace.json`; prune the clips freely with `./sweatcast cache prune`, but the pace file saves re-measuring), and `.logs/` holds each build's render log and `builds.jsonl`, one record per MP3 (each MP3 also gets a `<name>.build.json` beside it).
- `me/voices/`: private voices, looked in before `voices/`; `.takes/` holds designed takes before one is kept.
- `knowledge/tts-rules.md`: how to write for text-to-speech.
- `knowledge/voices.md`: how voices work, the engines, how the coach voices were made, and how to add one.
- `knowledge/movements.toml`: the movement catalog, every movement a session can use with its equipment, groups, spoken setup and cues, and the tags that say what it loads; also the fixed lists of equipment, tags and groups, and the kit presets. Read only through `tools/catalog.py`.
- `knowledge/injury-playbook.md`, `knowledge/kits.md`: programming references. The playbook gives each area's tags to avoid early; `kits.md` says what each kit usually holds and how to script around it. Where they disagree with `me/health.md`, the strictest wins, and anything health.md bans is out.
- `knowledge/exercise-science.md`: shared verified facts per movement, for the occasional one-line aside behind a form cue. Sessions add to `me/exercise-science.md`, not this file.
- `voices/`: the shipped voices, plus `smoke-test.draft.txt`, a one-minute check that also measures a new voice's pace.
- `sweatcast` (repo root): the one command. `./sweatcast <command>` runs each tool in the project's environment (`.venv`, Python 3.11); `./sweatcast help` lists the commands. Its implementation is `tools/sweatcast.py`, and `./sweatcast setup` runs `tools/setup.sh`, which makes the environment, so it needs no Python first. Skills and docs call tools only through it, so one permission rule covers them.
- `tools/setup.sh` (`./sweatcast setup`): one-time setup, safe to rerun: the Python environment (`uv sync` into `.venv`), `me/` from `me.example/` (or a migration of an existing one), the pre-push hook, and the default voice's model (`--all` for every voice, `--no-models` for none).
- `tools/build.sh` (`./sweatcast build`): draft to `.txt` and `.mp3` in one step (lint with `tools/tts_build.py`, then render with `tools/render.py`), then a copy of the MP3 to the profile's `deliver_to` folder. `--lint-only` stops after the lint; `--clips-only` renders ahead while a draft is still being written; only one render runs at a time, and a second waits for the first; `--allow-estimated` renders with a voice not yet measured. Exit codes are defined in `tools/cli.py`: 2 means the total ran more than three percent off plan, 3 means the voice hasn't been measured yet, 64 means the command itself was wrong.
- `tools/context.py`: the one reader and writer of the context files (profile, health, log, exercise science): the schema check, the profile's settings (`./sweatcast get default-voice | wpm | voices`, `./sweatcast deliver`), `./sweatcast log-session` to add a checked session line, and `./sweatcast check`, which lists any line still showing the template's `[hint]`, any feed not filled in, and anything the tools can't read. `tools/migrate.py` (`./sweatcast migrate`) brings an older context folder up to the current schema, backing it up first.
- `tools/draft.py`: the draft format and the timing layout the lint and the render share. `tools/engines.py`: the voice engines and the voice designer, and everything that depends on mlx-audio's or huggingface_hub's internals. `tools/cli.py`: the exit codes and the argument parser every tool uses. `tools/cache.py` (`./sweatcast cache`): the clip cache's size, and `prune` for clips no build has used in a while.
- `tools/voices.py` (`./sweatcast voices`): lists voices with their engine, measured pace and model; `measured`, `download`; `design` renders takes of a new voice from a written description (Qwen3-TTS VoiceDesign, pinned), and `keep` makes a take a private voice in `me/voices/` and adds it to the profile. `tools/char_weight.py` is OmniVoice's character-weight rule (Apache 2.0), vendored; every measured pace is counted in it.
- `tools/catalog.py`: loads and checks the movement catalog (plus any private movements) and matches a logged name to a movement, forgiving plurals and a leading side word. `tools/movements.py` (`./sweatcast movements`): the filter; prints the movements a kit allows (`--preset` or `--equipment`), minus any `--avoid` tags, by group, for the plan.
- `tools/coverage.py` (`./sweatcast coverage`): reads `me/log.md` and lists the muscle groups the last session left out and those the last seven days neglected, the movements to avoid, the last format and each movement's last load, for the plan.
- `tools/feeds.py` (`./sweatcast feeds`): fetches the profile's `[[feeds]]` (team results and schedules, weather, local and science headlines, weekly podcasts and puzzles, on this day) into `me/workouts/research/<date>-feeds.md`, which research reads before it searches, and prints only the weather.
- `tools/youtube.py` (`./sweatcast youtube`): lists recent unused videos from the profile's YouTube favorites and any series in progress, saves a video's transcript, and marks a series part as told, for the deep dive every other session; `puzzles` lists recent unused puzzle videos for the quiz.
- `tools/paths.py`: where everything lives (the engine, and the context folder from `SWEATCAST_HOME` or `me/`).
- `tools/hooks/`: the pre-push hook, `check-private.sh` (which checks every commit in a range, as the hook and CI both use it) and `private-paths`, the one list of paths that must never be pushed.
- `tests/`: fast checks for the lint, the timing layout, voices, voice design and the pace file, the context files and migration, the log, the movement catalog and its filter (`tests/test_catalog.py`, with a small catalog in `tests/fixtures/movements.toml`), the feed parsers, the YouTube series, `./sweatcast` and `build.sh`'s exit codes, the privacy hook, and a fresh copy running on `me.example/`, with no models, network or personal files (fixtures in `tests/fixtures/`). Run `./sweatcast test` after changing a tool; CI runs them on every push with Python 3.11.
- `pyproject.toml`, `uv.lock`, `.python-version`: the pinned Python environment.
- `docs/research/`: design notes, such as the productization research behind this layout.
- `VERSION`, `CHANGELOG.md`: the release number and what changed in each release.

A codegraph index (`.codegraph/`, git-ignored) is available for semantic code search through the codegraph MCP tool; after moving or renaming files, run `codegraph init` again to refresh it.

## Audio
`tools/render.py` voices each paragraph by cloning the voice's reference clip, with Chatterbox Turbo or Qwen3-TTS through `mlx-audio` (loaded in `tools/engines.py`), in the project's own environment (`.venv`, Python 3.11, pinned by `uv.lock`; no other app needed). Every tool runs there through `./sweatcast`, or under `SWEATCAST_PYTHON` if set; the Mac's own `python3` is never used. The default voice is the first in the profile's `[[voices]]`. On an M3 with 16 GB, Chatterbox Turbo renders at about 0.7 times the length of the speech and Qwen3 at about 1.3 to 1.45, so a 30-minute workout takes under 20 minutes with Chatterbox Coach. Turbo's decoding keeps the GPU busy, so two renders at once barely beat one and may not fit in memory; a render (or a voice design) holds a lock, so a second one waits, and rendering ahead with `--clips-only` is the way to overlap work. Model weights live in `~/.cache/huggingface/hub` (about 3.3 GB for Chatterbox Coach, 4.2 GB for Qwen3 Coach, 4.5 GB for the voice designer), downloaded at pinned revisions; keep only the ones a voice in use needs. The voices are named for the model that speaks them; a voice is a reference clip, not a tuned model (`knowledge/voices.md`).

## Releases
Versions follow Semantic Versioning, tracked in `VERSION` (and `pyproject.toml`) and `CHANGELOG.md`, and tagged `vX.Y.Z` on GitHub (RNCDev/sweatcast).
- Major: a change that breaks how existing drafts, voices, commands or the `me/` layout work, so something has to be migrated. Its CHANGELOG section says how, under "For forks". A change to a context file's format raises `SCHEMA` in `tools/context.py` and adds a step to `tools/migrate.py`, so a fork migrates with one command (`./sweatcast migrate`, which `./sweatcast setup` also runs).
- Minor: a new capability, such as an engine, a voice, a skill step or a tool option.
- Patch: fixes, tuning and doc corrections.

Listener content (sessions, research sheets, log entries) lives in `me/` and is never part of the engine's git. When a set of tool, skill or doc changes is finished and working, release it: add a dated section to `CHANGELOG.md`, bump `VERSION` and `pyproject.toml`, commit, tag (`git tag -a vX.Y.Z -m "..."`), push with tags, and publish a GitHub release (`gh release create vX.Y.Z --notes-file <that changelog section>`). Ask before pushing if it's unclear whether the work is done.
