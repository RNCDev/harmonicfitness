# 7.0.0: ingredients, not skeletons

Status: planned on 2026-10-22, after release 6.2.0; done in release 7.0.0 (2026-10-23). The judged run is
`docs/eval/results-2026-10-23.md`; the composer stays as an optional reference and the eval's baseline.

## Why

sweatcast's scripts sound mechanical, and the generation process is the main cause. Today the code
designs the workout and the LLM fills in blanks:

- `tools/session.py` (about 1,200 lines, with `tools/sessions.py` and `knowledge/sessions.toml`) picks
  the method, slot order, every dose and rest, and prints an `@@ <seconds> | <title>` marker per set,
  round or interval. The writer must script under exactly those markers.
- The workout skill (`.claude/skills/workout/SKILL.md`, about 5,800 words) piles rules on top, and the
  lint adds structure warnings.
- Each eval finding has turned into another composer branch or skill rule (6.1.0 and 6.2.0: coverage
  tie-break, station grouping, last-set seconds, machine rotation, name and opening warnings).

The goal for 7.0.0: the harness supplies rich, accurate **ingredients** (the listener, today's limits
and the movements they allow, coaching notes, physiology, equipment, research), and the LLM uses its
judgment and creativity to **design and write** the session. The harness keeps hard guarantees only
where something must never go wrong: safety, clean audio, total length.

## What stays

- The catalog (`knowledge/movements.toml`) with its loads, flags, coaching fields (`rep`, `feel`,
  `faults`), `[limit_cues]`, equipment and presets; `tools/catalog.py`'s `select`, which is the safety
  screen. This is the core asset.
- `knowledge/programming.md`, `injury-playbook.md`, `kits.md`, `tts-rules.md` (its Coaching voice
  section already fits this design).
- The context files and `tools/context.py`, `coverage`, `feeds`, `youtube`, research agents.
- The draft format (`@@ <seconds> | <label>`, `[pause]`, `[chime]`, `[hold]`) and the renderer,
  `build`, delivery, `log-session`, `backup`. The LLM still writes `@@` segments, because the render
  lays them on the clock, but it chooses them: a segment can be "the whole first round".
- The lint's text-to-speech checks, the paragraph-length check and the total within three percent.

## What changes

1. **`./sweatcast brief`** (new, `tools/brief.py`): one command, one Markdown brief for today:
   `./sweatcast brief --goal <goal> --minutes <n> (--kit | --preset | --equipment) [--limit ...] [--target ...]`.
   It prints (and with `--save <path>` also writes, plus a machine-readable menu, see 3):
   - **The listener:** name, Narrator tone, likes and dislikes, level, how today fits the week (from
     coverage: days since, sessions this week, patterns neglected, last format, last loads, latest
     feedback).
   - **Today's limits:** each limit's meaning, the clinician rules (including `Avoid:`), the
     `[limit_cues]` lines with the side filled in.
   - **The safe menu:** every movement `catalog.select` allows for this kit, level, limits, avoids and
     dislikes (allowed and healthy-side-only, marked), grouped by primary pattern, each with position,
     equipment, effort (conditioning), the coaching notes, easier and harder, seconds per rep or hold.
     Long, but it is the writer's whole palette. Include the kit's `Loads on hand`.
   - **The programming guide for this goal and level:** from `sessions.toml` and `programming.md`,
     as guidance, not a computed plan: dose ranges for the level (sets, reps, rest, work and rest
     seconds), hard-set and effort caps, the all-out sprint rule, warm-up, finisher and cool-down
     shares, the methods that suit this goal and length with one line each, and what a good session
     of this kind looks like (all major groups when sessions are frequent, multi-joint first, and so on).
   - **Equipment notes** from `kits.md` for the kit's equipment.
   Reuse code from `session.py` (`compose`'s request validation, limits, selection, likes, coverage)
   rather than rewriting it.

2. **The writer designs the session.** The workout skill's Step 2 becomes: read the brief, choose a
   method, movements, order, doses and timing that fit the guide, post the plan (a short table), then
   write. The writer picks the `@@` segments and their seconds (they must add up to the request).
   Every movement comes from the safe menu, nothing from memory: same rule as today, now checked (3).

3. **One new hard check: the menu.** The brief's `--save` writes `<draft>.menu.json` (the allowed ids,
   names and aliases, healthy-side-only ids with their side, the request). The draft's movements are
   declared once, in a first-line comment or a header the parser ignores, for example
   `@@ 0 | movements: goblet squat, floor press, dead bug` (decide the syntax in draft.py; it must not
   be spoken). `./sweatcast build` (lint stage) then fails when:
   - a declared movement isn't on the menu, or
   - the text names a catalog movement (by name or alias, longest match first) that isn't declared, or
   - there's no menu for the draft (so the check can't be skipped by accident).
   `log-session --movements` should take the same declared list.

4. **A short skill.** Rewrite `.claude/skills/workout/SKILL.md` to about a page: check-in (keep it),
   research agents (keep the templates), `./sweatcast brief --save`, design and post the plan, write
   (point to tts-rules for voice and to the brief for everything else), build, deliver, log, backup.
   Move anything that is knowledge rather than procedure into `knowledge/`. Keep the hard rules the
   tests check (every movement from the menu, `format: <method name>` in the log, red flags stop the
   session, health.md edits only at the check-in), adjusting the tests' wording checks.

5. **Lint: keep only what must hold.** Keep the text-to-speech line checks, the paragraph-length
   check, the total within three percent, and the menu check. Make the structure warnings (locator,
   countdowns, praise, exclamation points, name, openings, newsreader) advisory guidance in
   tts-rules, or drop them; decide by whether the first 7.0.0 eval shows the writer needs them.
   Relax the per-segment fill flags (80 to 110 percent) if the writer's own segments make them noisy.

6. **The composer leaves the main path.** Keep `./sweatcast session` for now as an optional
   "example shape" the writer may consult and as the eval's baseline; don't extend it. Remove the
   6.1.0 and 6.2.0 composer-only machinery later only if the eval shows the brief path is better
   (coverage tie-break, station grouping, last-set seconds, machine rotation, interval fallback).

7. **Eval.** Add a brief path to `docs/eval/`: `briefs.sh` (like `skeletons.sh`, running
   `brief --save` per case into `out/`), a writer brief (`writer.md` updated: design from the brief,
   no skeleton), and the same judge (five scores, warmth included). Run the same ten cases as run 4
   (c06, c08, c20, c30, c32, c34, c36, c38, c39, c40) plus the generic off-limits-ankle extra case
   (c41: listener d, general, 25 minutes, hotel-gym, `ankle=off-limits:<side>` and
   `foot=delicate:<side>`). Compare with run 4 (`docs/eval/results-2026-10-22-run4.md`). Success:
   safety stays 5 on every case, warmth and adherence rise, efficacy doesn't fall. If safety drops,
   fix the brief or the menu check before anything else.

## Why it's a major release

The workout flow changes (`brief` replaces `session` in the skill), the lint fails a draft with no
menu, and the draft gains a movements declaration. Context files don't change, so there's nothing to
migrate in `me/`; the CHANGELOG's "For forks" says to use `brief` and to declare movements.

## Order of work

1. `brief` (reusing `session.py`'s plumbing) with tests; check its output on a few kits and limits.
2. The menu file and the build check, with tests (a draft naming an unlisted movement fails; an
   alias inside a longer name doesn't false-match; a healthy-side-only movement is allowed).
3. The skill rewrite, and the tests that check its wording.
4. The eval path and the eleven-case run; write `results-<date>.md`.
5. Lint trimming, decided by the run.
6. CLAUDE.md, README, CHANGELOG, `VERSION` and `pyproject.toml` (and only the version line of
   `uv.lock`: the local `uv` is older than the one that wrote it), tag `v7.0.0`, push, GitHub release.

## Guardrails

- Never put the listener's personal details (health, side of an injury, location, log) in the engine,
  its tests, its eval cases or its docs. Eval listeners and cases stay invented and generic; the
  pre-push hook checks paths only, so read what you write.
- The safety screen (`catalog.select`) and the playbook's rules don't loosen in this refactor.
- `./sweatcast test` passes before any commit.
