Why it fits

  • sweatcast's data is already typed: limit rows, kits, coaches, the log, the menu. Each maps to a stock control.
  • The check-in is a conversation, but its answers are fields. Chat for the talk, a form for the facts.
  • Panels can show what the CLI hides: the segment timeline, the coach samples, the log.

Watch out for

  • Two places to answer. Make panel submits post into the chat so there's one record.
  • Most of your listening happens on a phone, so the bottom-sheet version is the real product.
  • Keep the panel set fixed and small. Let the agent pick and prefill, never invent layouts.

Option A in detail

A starting set of stock panels

The agent opens a panel by name with prefilled values. The panel writes back through the same tools the CLI uses, so the engine's checks still hold.

checkin

Minutes, goal, kit, sleep, soreness, each limit loosened or tightened. Feeds brief.

workout

Player, segment timeline, script, build status. Reads the build record.

coaches

The ten stock coaches with their 45-second samples, plus your web coaches.

limits

Each [[limits]] row: area, side, level, note. Clinician rules read-only.

log

Past sessions, feedback, coverage of the week.

profile

Name, kits and weights, likes, delivery.

keys

Your own keys for Claude and each voice service. Write-only: entered, tested, replaced, never shown again.

interests

Your interest graph: topics, feeds, favorites, what never to bring up, and what's been told.

Rules it keeps

  • Same rule as me/.env today: the agent never reads a key. The panel posts to the server, not the chat.
  • Shows set or not set and when it was last tested. Never the key, not even its last four characters.
  • "Test" sends one tiny request and reports the service's answer: works, wrong key, or out of credit.

Bring your own

  • Each listener pays their own Claude and voice bills. You host the app, not the usage.
  • Replace and delete are one tap. Deleting a key turns that service's coaches gray.

Hosting

Where to run it instead of Railway

The thing that decides it: local coaches need a GPU or an Apple Silicon Mac to render quickly, while web coaches run anywhere. The app also has to hold health data and keys.

Your own Mac, reached from your phone

MY PICK

Run the app on the Mac that already runs sweatcast. Reach it from your phone through Tailscale, or Cloudflare Tunnel with a login in front.

  • Local coaches work, about 5 minutes to render 30 minutes on Apple Silicon
  • Health data and keys never leave your computer
  • Keeps the "own computer" rule as it is
  • The Mac must be on and awake

Fly.io

Closest to Railway, but with persistent volumes and machines that stop when idle, so you pay little while nobody's using it.

  • Good home for the app and me/
  • Web coaches only, in practice

Fly.io or Render, plus Modal for renders

The app stays small. Each local-voice render goes to Modal, which starts a GPU, renders and stops, billed by the second.

  • Local coaches in the cloud, fast
  • Two services to run, and the voice files go to Modal

A small VPS (Hetzner, DigitalOcean)

One cheap always-on box with a real disk. Simple and cheap, but you handle updates, backups and TLS.

  • Local coaches work on its CPU, slowly (about 13 min per 30)

Hugging Face Spaces

Easy if you want others to try it. Free CPU tier, with GPU and persistent storage as paid upgrades.

  • Weak fit for private health data

Prices and plans change often. Check current pricing before choosing.

What to settle on any host

  • The agent. The skills need Claude running in the repo. That means the Claude Agent SDK on the server, using each listener's own Claude key.
  • Your me/ folder. It holds health data. It needs a persistent disk or the private backup repo, and the site needs a login.
  • Keys at rest. Today's me/.env is plain text on your own computer. On a shared server, keys should be encrypted, one set per listener.
  • House rule. CLAUDE.md says new listeners are set up only on their own computer. Any cloud host changes that, so the rule and the README would need updating. The Mac option doesn't.
