# 8.1.0 and 9.0.0: a standalone sweatcast Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A stranger clones sweatcast, says "set up sweatcast" in Claude Code, and reaches a first workout MP3 on any reasonable computer, rendered locally or by a cloud voice with their own key, in the voice of a coach they designed.

**Architecture:** Two releases. 8.1.0 (Part A) adds a shell readiness check (`./sweatcast doctor`), declines Claude Code cloud sessions, and makes setup survive missing ffmpeg, uv and git. 9.0.0 (Parts B, C, D) makes the local engines an optional uv extra (MLX, CUDA PyTorch, CPU PyTorch; Linux added), moves models into `models/`, adds four cloud engines behind the existing `say(text, seed)` contract, and replaces voices with persona folders in `me/personas/`, migrated from schema 3 to 4. Everything above the engine (lint, timing layout, loudness, MP3, build record, delivery) is unchanged. The voice dict that `render.py` and `engines.py` consume keeps its shape; personas and routes only change how it's built.

**Tech Stack:** Python 3.11 (uv, `uv.lock`), standard library only for HTTP (urllib), threads and MessagePack (a vendored minimal codec); POSIX sh for `tools/setup.sh` and `tools/doctor.sh`; unittest with local fake HTTP servers (`http.server`) in CI.

**Spec:** `docs/superpowers/specs/2026-10-24-standalone-sweatcast-design.md` (approved 2026-10-24). Its decisions are not reopened here; the builder's decisions are marked **Decided** with the reason.

## Global Constraints

- Priorities, in order: safe for the listener's body today, clean to the ear, worth listening to.
- Tools run only through `./sweatcast`. Context files are read and written only through `tools/context.py`; paths come only from `tools/paths.py`.
- Engine contract: `say(text, seed)` returns 16-bit mono PCM at 24 kHz (`engines.SR = 24000`). Cloud engines may also take `previous_text=` and `next_text=` keyword arguments; local engines ignore them.
- Pace is keyed `"<clip key>|<engine>|<model>"` (`voices._rate_key`); keys must stay byte-identical through migration (this Mac's: `e5488e8c8349|chatterbox|mlx-community/chatterbox-turbo-fp16`, `e5488e8c8349|chatterbox|ResembleAI/chatterbox-turbo`, `fdb9e1b9e92f|qwen3|mlx-community/Qwen3-TTS-12Hz-1.7B-Base-bf16`).
- A new engine renders a session only after the smoke test measures it (exit 3 until then).
- An API key lives only in `me/.env`. Never printed, logged, put in a build record, in a cache key, in `me/`'s backup repo, or in the chat. Claude never reads, prints or copies `me/.env` (denied in `.claude/settings.json` since commit 17598aa). No `grep -r`, `cat` or `find` over `me/` as a whole.
- CI: Ubuntu, plain `python -m unittest discover tests`, no `uv sync`, so no third-party packages, no models, no network, no personal files. Any import of `imageio_ffmpeg`, `numpy`, `mlx`, `torch` stays inside a function and is guarded.
- ElevenLabs, Cartesia and Deepgram are labeled "not yet tried live" in `knowledge/services.toml` (`tried_live = false`), the readiness check, setup and docs. Fish Audio becomes `tried_live = true` only after the live checks in Task 18 pass.
- Processor (CPU) rendering ships labeled "experimental, speed unknown, likely slow" until this computer's own smoke test has measured its speed.
- Floors (cautious guesses, stated as such): 8 GB memory, 6 GB free disk for the local route only.
- Cloud session: `CLAUDE_CODE_REMOTE=true` declines; `SWEATCAST_ALLOW_CLOUD_SESSION=1` overrides for developers.
- Release steps per CLAUDE.md, but ask the listener before any merge to main, push, tag push or GitHub release.
- Never put personal details in the engine, its tests or examples.

## Review Focus

- **A `me/.env` written by hand in an odd way** (quotes around the value, `export NAME=value`, Windows CRLF line ends, a UTF-8 BOM, spaces around `=`): the key is still found. Test in Task 7 (`test_env_formats_all_read`).
- **A cloud build interrupted partway** (network drop or 429s past the retries after 30 of 150 paragraphs): the rendered clips stay cached, the rerun sends only the rest, and the cost estimate and ceiling count only what's not cached. Test in Task 10 (`test_interrupted_cloud_build_resumes_without_resending`).
- **Migrate run twice, or after a half-finished run** (a persona folder already exists): nothing is overwritten or duplicated, and the second run says there's nothing to do. Test in Task 15 (`test_migrate_4_is_idempotent_and_never_overwrites_a_persona`).
- **A coach name that isn't a safe folder name** ("Coach Zoë", "Coach O'Neil", "Coach Ana María"): an ASCII slug for the folder, the display name kept, and lookup by either. Test in Task 8 (`test_slug_and_lookup_with_accents_and_apostrophes`).
- **A profile `render` list with an unknown or misspelled route** (`"fish-audio"`, `"locl"`): `./sweatcast check` names it, and a build skips it with one plain line rather than a traceback. Test in Task 9 (`test_unknown_route_is_reported_and_skipped`).

### Task 10 (Part C): The cloud engine core, and the render's cloud path

**Files:**

**Decided:**

- Retries: up to 6 tries on 429, 5xx and network errors, waiting `min(2 ** n, 30)` seconds with jitter, honoring `Retry-After` when present (tests pass a zero-wait clock).
- Concurrency per service from `services.toml` (Fish 4, ElevenLabs 2, Cartesia 2, Deepgram 4: under each service's lowest paid plan limit); render uses a `ThreadPoolExecutor` for cloud only and sums pace after.

Over the ceiling exits `cli.ISSUES` (1) before sending. `--follow` or `--clips-only` on a cloud route exits `cli.USAGE` (64) with "Rendering ahead is off for a cloud voice: every re-render would be billed. Read only through `cloud.services()`.

**Interfaces:**
