# Setup: a new listener's context

Goal: a stranger hears their first workout within minutes. The **quick start** asks one round of questions, has them choose a coach (one of the ten local coaches sweatcast ships, by ear from short samples, where local voices run; else the default web coach of the service they add a key for), and ends with a ten-minute workout. Everything else (interests, taste, feeds, the delivery folder, a web coach of their own) is **finish setting me up**, whenever they like. Everything personal goes in `me/` (git-ignored); never edit the engine (tools, skills, `knowledge/`) for one listener.

The listener may be a stranger who has read nothing: explain each step in a line, in plain words, and never send them to the README.

## Step 0: what this computer can do

Run `./sweatcast doctor` first and relay what matters in two or three plain lines: the computer, whether local voices work here, and anything missing.
- **Claude Code on the web** (doctor's report starts "This is Claude Code on the web"): see "On Claude Code on the web" below before anything else: a new listener isn't set up there.
- **uv missing:** ask once (AskUserQuestion) whether to install it with Astral's official installer, which needs no admin rights; it runs a downloaded script, so ask first. On yes, `./sweatcast setup --install-uv --no-models` (it installs uv, then carries on as in Step 1).
- **No local voices here** (an Intel Mac, or below the memory or disk floor): say so now, with doctor's reason. Audio then comes from a web coach, through a voice service with the listener's own key (Keys, below).
- ffmpeg isn't a prerequisite: the Python environment brings its own. git isn't either: outside a git checkout (a zip download), setup skips only the privacy hook.

## The fork: where the voice is made

Right after doctor's lines, before any question, lay out the one big choice in setup, in a few plain lines:
- **On this computer (local):** free and private; nothing leaves the computer. A one-time download first, about 4 GB in all (the voice engine, Pocket TTS, and the speech recognizer that checks every line). Rendering is quick: a 30-minute workout in about five minutes on an Apple Silicon Mac, ten to fifteen on a PC's processor, less with an NVIDIA card, mostly overlapped with the script being written. The coach is one of ten that ship with sweatcast, five men and five women of different ages and styles, each with a short sample to choose by ear; a local coach speaks only on a computer that runs local voices.
- **Through a web service (a web coach):** no download, and a 30-minute workout renders in a minute or two. Pay-as-you-go with a key of their own and no subscription: about $0.27 (Gemini), $0.30 (Fish Audio), $0.50 (Inworld) or $1.60 (ElevenLabs) a workout, prices approximate, and about a cent to design a voice. Each workout's script, which can mention injuries, goes to the service. They start with a stock web coach, or pick a voice of their own by ear from an audition of candidates designed from a description, and it speaks from any computer with the key.
- **Which way this computer starts:** local wherever it runs (an Apple Silicon Mac, or a Windows or Linux PC), else web, with doctor's reason. They can say "start with a web coach" instead. Either way they hear their coach before the first workout (step 4 of the quick start).
- **Revisiting it:** nothing is locked in, and both can live side by side, since each coach speaks on its own route: "switch coach" picks another of the ten (or any coach they have), "I want a new coach" makes a web coach of their own, "add a voice key" adds a web service, and "set up local voices" installs the local engine where it runs.

## Step 1: the machine

Run `./sweatcast setup --no-models` with `run_in_background: true`, and ask the quick start's questions while it runs. It makes the Python environment with uv, copies `me.example/` to `me/` if there's no `me/profile.md` yet (with `setup = "quick"` in `me/settings.toml`), or brings an existing one up to this version's format (backing it up first), and installs the git hook that refuses to push `me/`. The local engine and its model come later, once the audio route is settled. If it stops, relay its one-line fix and rerun it once they say it's done.

If `me/profile.md` already has real answers, this is an update: ask only about what they want to change (the reference sections below say how each part is written), and skip the rest.

## The quick start (a new listener)

1. **One AskUserQuestion round, four questions:**
   - **Name:** what the coach should call them (options: "Use my first name" and "No name", with their name through Other). It goes in the settings as `name`.
   - **Experience:** novice (new to training, or back after a long break), experienced (trains regularly, knows the common lifts), advanced (trains hard, wants harder variations). It becomes `experience`.
   - **Kit:** bodyweight only, a hotel room, a gym, or "what's at home" through Other (dumbbells, bands, a bench...). It becomes the first `[[kits]]` row (Kits, below).
   - **Injuries:** "None" (Recommended) or describe them through Other. Say plainly, once: sweatcast isn't medical advice, a clinician's instructions override everything, and red flags (can't bear weight, rapidly increasing swelling, numbness, giving way, getting worse after a week or two) mean seeing a clinician before training. Each injury they name becomes a `[[limits]]` row (Health, below); ask a follow-up only if the area or the side isn't clear.
2. **Audio,** without a question where doctor settles it: local wherever it works, started now (Step 4 below) so it downloads while they choose a coach and during the first workout's research. Where local doesn't run, it's a web coach: run the keys step (Keys, below) for one service.
3. **Write** `name`, `experience`, the kit and any limits (Writing the files, below). Leave the other template lines as they are: with `setup = "quick"`, `./sweatcast check` lists them as notes, not issues.
4. **Their coach,** chosen by ear, so the voice in their earbuds is no surprise:
   - **Local:** one AskUserQuestion, "What kind of coach do you like?", with four styles (each option names its coaches): **Calm and experienced** (Andy, Sam, Helen), **Upbeat and energetic** (Marcus, Maya, Kate), **Easygoing and friendly** (Theo, Rosa), **Direct and precise** (Callum, Claire). Then send that style's samples, each 45 seconds of the coach leading a warm-up with a countdown (`coaches/coach-<name>-local/sample.mp3`, such as `coaches/coach-maya-local/sample.mp3`; SendUserFile if it's available, else `./sweatcast show <file>`, which opens its folder with it selected, so they can double-click it), with one line per coach from `./sweatcast coaches`, and ask which one (AskUserQuestion, the style's coaches as options, "Hear another style" through Other). Every one is measured and ready: no smoke test, nothing to make. The coach a workout uses becomes the one every later workout uses until they ask for another ("switch coach"), so nothing else is written.
   - **A web coach:** the stock web coach for the service they added a key for: Coach Reed (Fish Audio), Coach Ellis (ElevenLabs), Coach Nolan (Gemini) or Coach Owen (Inworld), all from one description of a warm baritone trainer in his forties. None ships with a voice, since a designed voice belongs to the account that made it: his is designed fresh in their account. Say so first, in a line, with what it costs: about $0.01 on Fish Audio or Gemini; Inworld doesn't publish its design cost; on ElevenLabs it takes one of the account's custom voice slots (Free keeps 3). Say the privacy line (Audio, below) here too. Then make him now rather than at the first build, `./sweatcast coaches make "<name>"`, and send the test clip it saves, `me/coaches/<slug>/sample.mp3`, the same way. With the clip, one line: if he isn't right, "I want a new coach" auditions voices to pick from by ear, now or any time.
5. **A ten-minute first workout:** run the `workout` skill, strength at ten minutes (the check-in asks only how they're coming in today), passing the coach they chose. It's the end-to-end check. Make sure they can find the MP3: SendUserFile if it's available, else `./sweatcast show <the MP3>` (Finder or Explorer opens with it selected).
6. **Getting it to their phone,** one AskUserQuestion right after the first workout: "Where should workouts go, so they reach your phone?", with iCloud Drive, Google Drive and Dropbox (only the ones whose folder exists on this computer; check with `ls`) and "Keep them on this computer". A synced choice sets `deliver_to` (Delivery, below) and copies this first MP3 there too.
7. **Then, in two lines:** they can say "switch coach" any time for another of the ten, or "I want a new coach" for a web coach of their own (needs a voice key; a few minutes: one question, then an audition of voices to pick from by ear; offered, never required), and "finish setting me up" for interests, teams and feeds, which the workout's stories come from. Suggest backing up `me/` (Keep it safe, below).

## Finish setting me up

Runs the rest of the interview, AskUserQuestion with at most three rounds of up to four questions, in this order: likes and dislikes, interests and taste, delivery (unless the quick start set it), a web coach of their own if they want one (the `coach` skill's quick coach; it needs a voice key), and a neighborhood and city for local news and weather. Then Feeds and `./sweatcast check` (Writing the files), and remove the `setup = "quick"` line and its comment from `me/settings.toml`, so check holds every line to the full standard again.

## On Claude Code on the web

sweatcast doesn't set up a new listener on Claude Code on the web: it runs in Claude Code on their own computer. With no `me/profile.md` (or no context folder at all), say so in two plain lines: install the Claude desktop app (https://claude.com/download), open its **Code** tab, and say "Can you use https://github.com/RNCDev/sweatcast and set me up?"; then stop. A listener who is already set up and has attached their own private `sweatcast-me` repo keeps working there with their web coaches (doctor's "Claude Code on the web" section says what's set: the key as an environment setting, the hosts to allow); help with that, but never start a new setup there.

## Reference: how each part is written

**Kits.** Each kit becomes one `[[kits]]` row in `me/training.md`'s settings: a `name` and the `equipment` ids it holds, from the catalog's equipment list (near the top of `knowledge/movements.toml`; the `[presets.*]` tables there are kits to start from: bodyweight, hotel-room, hotel-gym, full-gym). The first kit is the default. For free weights, ask which weights are there and write them as `weights` (equipment id = the weights, lightest to heaviest) with `unit` (`"lb"` or `"kg"`), for example `weights = { dumbbells = [10, 15, 20], kettlebell = [30] }`, so the brief prints what's on hand and the session prescribes only those. Also copy each kit into the prose under Equipment kits.

**Likes and dislikes.** Movements they enjoy or want left out. Resolve each name against the catalog (`./sweatcast movements --equipment <ids>` prints movement names, which the catalog resolves to ids) and put the ids in `likes` and `dislikes`; a name the catalog doesn't know goes in the profile's prose, not in the list.

**Health.** Walk each injury into one `[[limits]]` row in the settings block of `me/health.md` (the template, `me.example/health.md`, shows one):
- `area`, from the catalog's list of thirteen: foot, ankle, calf, knee, hamstring, hip, groin, low-back, rib, shoulder, elbow, wrist, neck. Spell it as written here, with the hyphen in low-back.
- `side`: left, right or both.
- `level`: off-limits means nothing that loads the area at all; delicate means nothing that loads it hard, no impact and no fast work. Offer both in those words and let the clinician's words decide; when unsure, off-limits.
- `note`: the clinician's words, short. Put them word for word under `## Clinician rules` too; each is followed literally. An injury in none of the thirteen areas gets no row: write it in the prose list as "- Unlisted: <what>", and put any movements or flags to avoid for it under `## Clinician rules` as a line "Avoid: <movements or flags>" (catalog ids or names, flags from its `flags` list), which `./sweatcast brief` applies on every run; a word that is neither stops the brief. The playbook's "Unlisted injuries" says what to do.
- `rehab` and `flags` stay empty unless the clinician named a rehab movement or something else to avoid; `flags` values come from the catalog's fixed `flags` list.
Add the injury and its programming to the prose list under Active injuries too. No injuries: leave "None right now." and no rows. Writing `me/health.md` asks the listener's permission; that's expected, since it's the most private file.

**Interests and taste** (all in `me/content.md`). Teams, topics, YouTube channels for deep dives, puzzles, books, local news, and anything never to bring up; then favorite shows, books, music, comedians, restaurants and drinks, with ratings if they have them. Interests become `[[interests]]` rows in the profile's settings (name, slot from `knowledge/content.toml`, detail); favorites go under `## Taste`; and find a feed for each taste area that has one.

**Audio.** How the workouts become audio. Offer what doctor's Audio routes section says works here:
- **Local** (where it works): free, private, on this computer; the engine (Pocket TTS) and the take checker are a one-time download of about 4 GB, and a 30-minute workout renders in about five minutes on an Apple Silicon Mac, ten to fifteen on a PC's processor. The ten stock local coaches use it; the profile's `render` list is `["local"]`.
- **A web coach:** a voice a service designs from a description and saves in the listener's own account, with their own key (Keys, below). A web coach always speaks through its own service, whatever the `render` list says, so adding a key changes nothing there. No subscription is needed anywhere.
- **The privacy line,** said once, plainly, before the first web build: every service receives the workout's script, which can mention their injuries ("easy on that left knee"); Gemini's free tier uses what it's sent for training, with human review; roughly what a workout costs there (approximate; prices change); and the key is stored in `me/.env` on this computer only, never backed up or shown, and removed by deleting its line.
- With a web coach, also write `cloud_max_chars = 30000` in `me/settings.toml` (a 40-minute workout with room for retakes: about $0.45 on Fish Audio, $0.75 on Inworld, $2.40 on ElevenLabs): tell them the figure and that a build over it stops before sending.

**Keys.** `./sweatcast keys` prints "set" or "not set" for each web service, never a key. With none set and a web coach wanted, recommend **Fish Audio** for a first key (no minimum, among the cheapest, the simplest sign-up) and walk them through it in short numbered steps: sign up at https://fish.audio, add a few dollars of credit under billing, then make a key at https://fish.audio/app/api-keys (Create New Key; copy it, since it may not be shown again). Mention the others in one line as more choices, each with its key page; more keys mean more voices to choose from in an audition:
- **Fish Audio** (https://fish.audio/app/api-keys): prepaid credit, no minimum; about $0.30 a workout, among the cheapest.
- **ElevenLabs** (https://elevenlabs.io/app/settings/api-keys): the Free account works within its 3 custom voices and its monthly allowance (about half a workout), with prepaid pay-as-you-go usage ($5 minimum) beyond it; about $1.60 a workout on the natural model, $0.80 on the faster one. Not yet tried on a Free account: say so. The key needs two permissions when it's made: Text to Speech, and Voices: write.
- **Gemini** (https://aistudio.google.com/apikey): a key from Google AI Studio (not Google Cloud), with prepaid credit ($5 minimum); about $0.27 a workout until the end of 2026, about $0.54 from 2027. Its free tier uses requests for training with human review, its terms say it's not for consumer use, and it's for adults (18+): say so.
- **Inworld** (https://platform.inworld.ai, Settings > API Keys): the On-Demand plan, $0 a month with prepaid credit ($10 minimum); about $0.50 a workout.

Then add the key:
- **On their computer** (a terminal, VS Code or the desktop app): `./sweatcast keys init <service>` (fish, elevenlabs, gemini or inworld) adds an empty line to `me/.env`, and `./sweatcast keys open` opens that file in the computer's own text editor. They paste the key after the `=` and save (say exactly that: "paste it right after the = sign, with no spaces, then save and close"). Never ask for the key in the chat, and never open, print or copy `me/.env` yourself. `./sweatcast keys` confirms it's set.

**Delivery.** Where finished MP3s should go: a folder that syncs to their phone (iCloud Drive is `~/Library/Mobile Documents/com~apple~CloudDocs/<folder>`, Google Drive for desktop is `~/Library/CloudStorage/GoogleDrive-*/My Drive/<folder>` on a Mac and usually `G:/My Drive/<folder>` on Windows (forward slashes), Dropbox is `~/Library/CloudStorage/Dropbox/<folder>`), or nowhere, keeping them in each workout's folder in `me/workouts/`. Say that once a build's copy lands there, the local MP3 is removed and only the script's text stays, so this folder is where the audio lives. Check the folder exists with `ls`, and offer to create the subfolder. It is the `deliver_to` setting in `me/settings.toml`, a folder or a list of them, one per computer the listener renders on (each build copies to the ones that exist there); a request to change where workouts go runs this part alone.

**Writing the files.**
- The listener's files: fill in the placeholders the answers cover (the template is `me.example/`), and delete lines the user has nothing for (the quick start leaves the rest for later). Each Markdown file keeps its `+++` TOML block at the top, holding the settings the tools read; edit values in place, and the prose below is for Claude only. Each setting has one home:
  - `me/profile.md`: `name`, `experience`; the Basics (neighborhood) and Listening setup prose.
  - `me/training.md`: `likes`, `dislikes`, one `[[kits]]` table per kit (`name`, `equipment`, and for free weights `weights` and `unit`); the Default session prose, and Equipment kits notes the settings can't hold.
  - `me/content.md`: `youtube_favorites` and `puzzles` (@handles without the @), `[[interests]]`, one `[[feeds]]` table per feed (`label`, `kind`, `value`); the Content (with "Never bring up") and Taste prose.
  - `me/settings.toml` (plain TOML, no prose): `setup`, `render` (the audio routes, in order), `deliver_to`, `words_per_minute` and, with a web coach, `cloud_max_chars`.
  - `me/health.md`: the `[[limits]]` rows and the injuries' prose (Health, above).
- **Feeds** (finish setting me up). Weather: the neighborhood's latitude and longitude, rounded to two decimals. Teams: find each team's ESPN path (the `sport/league/team` part of its ESPN team page URL, such as `hockey/nhl/nj` or `soccer/usa.1/10739`) with a web search. Local news: one or two outlets' RSS feeds for the city. Keep the shipped science and puzzle feeds unless the user doesn't want them. YouTube handles: check each one resolves (`https://www.youtube.com/@<handle>`).
- Then run `./sweatcast check`. It lists every line still showing the template's `[hint]`, any feed not filled in, a missing experience level, likes or dislikes the catalog doesn't know, kit equipment not in the catalog, a malformed `[[limits]]` row (which would apply no limit at all), an unknown rehab id or one that isn't a rehab movement, a bad `flags` value, an injury written in prose with no `[[limits]]` row, and anything the tools can't read, with line numbers; fix each issue until there are none (notes, such as no delivery folder, a stock web coach made the first time it's used, or what the quick start left for later, are fine). After filling in feeds, run `./sweatcast feeds` once, fix or remove any source it lists under "Couldn't fetch", and run it again.

## Step 4: the local engine, when the route includes local

If doctor (or `./sweatcast models adopt --dry-run`) found sweatcast's models already downloaded elsewhere, offer to move them (`./sweatcast models adopt`) rather than download again. Say the size (about 4 GB in all: PyTorch, Pocket TTS's 0.6 GB model and the 2.5 GB take checker; no account or login needed), then run `./sweatcast setup --local` with `run_in_background: true`. It skips what's done. A computer that had an older sweatcast keeps models nothing uses now: `./sweatcast models` lists them with their sizes, and they can delete those folders to free the space (offer it; never delete them unasked).

## Keep it safe

- Ask whether they have a GitHub account. Without one, say `me/` stays on this computer and everything works; to keep a copy, they can copy the `me` folder now and then to somewhere private (it holds their health notes). With one, suggest backing up `me/` as its own private git repo: `git init` inside `me/`, commit, and push to a private remote (`gh repo create sweatcast-me --private --source . --push`). The engine's git ignores `me/`, so the two never mix, and the pre-push hook blocks `me/` from the public repo.
- Summarize what was written, in a few lines, and where to change it later ("ask me to update your profile").
