# Setup: a new listener's context

Goal: a stranger hears their first workout within minutes. The **quick start** asks one round of questions, uses a stand-in coach (Coach Andy where local voices run, else the default web coach of the service they add a key for), and ends with a ten-minute workout. Everything else (interests, taste, feeds, the delivery folder, their own coach) is **finish setting me up**, whenever they like. Everything personal goes in `me/` (git-ignored); never edit the engine (tools, skills, `knowledge/`) for one listener.

The listener may be a stranger who has read nothing: explain each step in a line, in plain words, and never send them to the README.

## Step 0: what this computer can do

Run `./sweatcast doctor` first and relay what matters in two or three plain lines: the computer, whether local voices work here, and anything missing.
- **Claude Code on the web** (doctor's report starts "This is Claude Code on the web"): see "On Claude Code on the web" below before anything else: a new listener isn't set up there.
- **uv missing:** ask once (AskUserQuestion) whether to install it with Astral's official installer, which needs no admin rights; it runs a downloaded script, so ask first. On yes, `./sweatcast setup --install-uv --no-models` (it installs uv, then carries on as in Step 1).
- **No local voices here** (an Intel Mac, or below the memory or disk floor): say so now, with doctor's reason. Audio then comes from a web coach, through a voice service with the listener's own key (Keys, below). **The processor only** (Windows or Linux without an NVIDIA card): local voices work but are experimental, speed unknown and likely slow; offer a web coach too.
- ffmpeg isn't a prerequisite: the Python environment brings its own. git isn't either: outside a git checkout (a zip download), setup skips only the privacy hook.

## The fork: where the voice is made

Right after doctor's lines, before any question, lay out the one big choice in setup, in a few plain lines:
- **On this computer (local):** free and private; nothing leaves the computer. A one-time download of the engine and model first: about 4 GB on a Mac, up to 8 GB on Windows or Linux. Rendering takes time: on an Apple Silicon Mac about 0.7 times the length of the speech, so a 30-minute workout takes under 20 minutes, mostly overlapped with the script being written; on the processor only, experimental and much slower. A local coach speaks only on a computer that runs local voices.
- **Through a web service (a web coach):** no download, and a 30-minute workout renders in a minute or two. Pay-as-you-go with a key of their own and no subscription: about $0.27 (Gemini), $0.30 (Fish Audio), $0.50 (Inworld) or $1.60 (ElevenLabs) a workout, prices approximate, and about a cent to design a voice. Each workout's script, which can mention injuries, goes to the service. They pick the voice by ear from an audition of candidates designed from a description, and it speaks from any computer with the key.
- **Which way this computer starts:** local where it runs fast (Apple Silicon, or an NVIDIA card), else web, with doctor's reason. They can say "start with a web coach" instead. Either way they hear a short test clip of their stand-in coach before the first workout (step 4 of the quick start).
- **Revisiting it:** nothing is locked in, and both can live side by side, since each coach speaks on its own route: "I want a new coach" makes a coach of either kind at any time, "add a voice key" adds a web service, and "set up local voices" installs the local engine where it runs.

## Step 1: the machine

Run `./sweatcast setup --no-models` with `run_in_background: true`, and ask the quick start's questions while it runs. It makes the Python environment with uv, copies `me.example/` to `me/` if there's no `me/profile.md` yet (the stand-in coaches included, and `setup = "quick"` in the profile), or brings an existing one up to this version's format (backing it up first), and installs the git hook that refuses to push `me/`. The local engine and its model come later, once the audio route is settled. If it stops, relay its one-line fix and rerun it once they say it's done.

If `me/profile.md` already has real answers, this is an update: ask only about what they want to change (the reference sections below say how each part is written), and skip the rest.

## The quick start (a new listener)

1. **One AskUserQuestion round, four questions:**
   - **Name:** what the coach should call them (options: "Use my first name" and "No name", with their name through Other). It goes in the settings as `name`.
   - **Experience:** novice (new to training, or back after a long break), experienced (trains regularly, knows the common lifts), advanced (trains hard, wants harder variations). It becomes `experience`.
   - **Kit:** bodyweight only, a hotel room, a gym, or "what's at home" through Other (dumbbells, bands, a bench...). It becomes the first `[[kits]]` row (Kits, below).
   - **Injuries:** "None" (Recommended) or describe them through Other. Say plainly, once: sweatcast isn't medical advice, a clinician's instructions override everything, and red flags (can't bear weight, rapidly increasing swelling, numbness, giving way, getting worse after a week or two) mean seeing a clinician before training. Each injury they name becomes a `[[limits]]` row (Health, below); ask a follow-up only if the area or the side isn't clear.
2. **Audio,** without a question where doctor settles it: local where it works fast (Apple Silicon, or an NVIDIA card), started now (Step 4 below) so it downloads during the first workout's research. Where local doesn't run, or runs only on the processor, it's a web coach: run the keys step (Keys, below) for one service.
3. **Write** `name`, `experience`, the kit and any limits (Writing the files, below). Leave the other template lines as they are: with `setup = "quick"`, `./sweatcast check` lists them as notes, not issues.
4. **Their coach for now** is a stand-in, a warm baritone trainer in his forties, and they hear a short test clip of him before the first workout, so the voice in their earbuds is no surprise:
   - **Local:** Coach Andy, measured already on the local engine, so no smoke test is needed. His fifteen-second test clip ships with him: send `me/personas/coach-andy-local/sample.mp3` (SendUserFile if it's available, else `./sweatcast show <file>`, which opens its folder with it selected, so they can double-click it).
   - **A web coach:** the default for the service they added a key for: Coach Reed (Fish Audio), Coach Ellis (ElevenLabs), Coach Nolan (Gemini) or Coach Owen (Inworld), all from one description. None ships with a voice, since a designed voice belongs to the account that made it: his is designed fresh in their account. Say so first, in a line, with what it costs: about $0.01 on Fish Audio or Gemini; Inworld doesn't publish its design cost; on ElevenLabs it takes one of the account's custom voice slots (Free keeps 3). Say the privacy line (Audio, below) here too. Then make him now rather than at the first build, `./sweatcast coaches make "<name>"`, and send the test clip it saves, `me/personas/<slug>/sample.mp3`, the same way.
   - **With the clip, one line:** if he isn't right, "I want a new coach" auditions voices to pick from by ear, now or any time; otherwise the workout goes ahead with him.
5. **A ten-minute first workout:** run the `workout` skill, strength at ten minutes (the check-in asks only how they're coming in today), passing the stand-in as the coach. It's the end-to-end check. Make sure they can find the MP3: SendUserFile if it's available, else `./sweatcast show <the MP3>` (Finder or Explorer opens with it selected).
6. **Getting it to their phone,** one AskUserQuestion right after the first workout: "Where should workouts go, so they reach your phone?", with iCloud Drive, Google Drive and Dropbox (only the ones whose folder exists on this computer; check with `ls`) and "Keep them on this computer". A synced choice sets `deliver_to` (Delivery, below) and copies this first MP3 there too.
7. **Then, in two lines:** they can say "I want a new coach" for a coach of their own (a few minutes: one question, then an audition of voices to pick from by ear; offered, never required), and "finish setting me up" for interests, teams and feeds, which the workout's stories come from. Suggest backing up `me/` (Keep it safe, below).

## Finish setting me up

Runs the rest of the interview, AskUserQuestion with at most three rounds of up to four questions, in this order: likes and dislikes, interests and taste, delivery (unless the quick start set it), their own coach (the `coach` skill's quick coach), and a neighborhood and city for local news and weather. Then Feeds and `./sweatcast check` (Writing the files), and remove the `setup = "quick"` line and its comment from the profile's settings, so check holds every line to the full standard again.

## On Claude Code on the web

sweatcast doesn't set up a new listener on Claude Code on the web: it runs in Claude Code on their own computer. With no `me/profile.md` (or no context folder at all), say so in two plain lines: install the Claude desktop app (https://claude.com/download), open its **Code** tab, and say "Can you use https://github.com/RNCDev/sweatcast and set me up?"; then stop. A listener who is already set up and has attached their own private `sweatcast-me` repo keeps working there with their web coaches (doctor's "Claude Code on the web" section says what's set: the key as an environment setting, the hosts to allow); help with that, but never start a new setup there.

## Reference: how each part is written

**Kits.** Each kit becomes one `[[kits]]` row in the profile's settings: a `name` and the `equipment` ids it holds, from the catalog's equipment list (near the top of `knowledge/movements.toml`; the `[presets.*]` tables there are kits to start from: bodyweight, hotel-room, hotel-gym, full-gym). The first kit is the default. For free weights, ask which weights are there and write them as `weights` (equipment id = the weights, lightest to heaviest) with `unit` (`"lb"` or `"kg"`), for example `weights = { dumbbells = [10, 15, 20], kettlebell = [30] }`, so the brief prints what's on hand and the session prescribes only those. Also copy each kit into the prose under Equipment kits.

**Likes and dislikes.** Movements they enjoy or want left out. Resolve each name against the catalog (`./sweatcast movements --equipment <ids>` prints movement names, which the catalog resolves to ids) and put the ids in `likes` and `dislikes`; a name the catalog doesn't know goes in the profile's prose, not in the list.

**Health.** Walk each injury into one `[[limits]]` row in the settings block of `me/health.md` (the template, `me.example/health.md`, shows one):
- `area`, from the catalog's list of thirteen: foot, ankle, calf, knee, hamstring, hip, groin, low-back, rib, shoulder, elbow, wrist, neck. Spell it as written here, with the hyphen in low-back.
- `side`: left, right or both.
- `level`: off-limits means nothing that loads the area at all; delicate means nothing that loads it hard, no impact and no fast work. Offer both in those words and let the clinician's words decide; when unsure, off-limits.
- `note`: the clinician's words, short. Put them word for word under `## Clinician rules` too; each is followed literally. An injury in none of the thirteen areas gets no row: write it in the prose list as "- Unlisted: <what>", and put any movement ids or flags to avoid for it under `## Clinician rules` as a line "Avoid: <ids or flags>" (ids from the catalog, flags from its `flags` list), which `./sweatcast brief` applies on every run. The playbook's "Unlisted injuries" says what to do.
- `rehab` and `flags` stay empty unless the clinician named a rehab movement or something else to avoid; `flags` values come from the catalog's fixed `flags` list.
Add the injury and its programming to the prose list under Active injuries too. No injuries: leave "None right now." and no rows. Writing `me/health.md` asks the listener's permission; that's expected, since it's the most private file.

**Interests and taste.** Teams, topics, YouTube channels for deep dives, puzzles, books, local news, and anything never to bring up; then favorite shows, books, music, comedians, restaurants and drinks, with ratings if they have them. Interests become `[[interests]]` rows in the profile's settings (name, slot from `knowledge/content.toml`, detail); favorites go under `## Taste`; and find a feed for each taste area that has one.

**Audio.** How the workouts become audio. Offer what doctor's Audio routes section says works here:
- **Local** (where it works): free, private, on this computer; the engine and model are a one-time download (about 4 GB on a Mac, up to 8 GB on Windows or Linux), and Apple Silicon renders a 30-minute workout in about 20 minutes. On the processor, say it's experimental and slow. Local coaches use it; the profile's `render` list orders the local engines (`["local"]`) and nothing else.
- **A web coach:** a voice a service designs from a description and saves in the listener's own account, with their own key (Keys, below). A web coach always speaks through its own service, whatever the `render` list says, so adding a key changes nothing there. No subscription is needed anywhere.
- **The privacy line,** said once, plainly, before the first web build: every service receives the workout's script, which can mention their injuries ("easy on that left knee"); Gemini's free tier uses what it's sent for training, with human review; roughly what a workout costs there (approximate; prices change); and the key is stored in `me/.env` on this computer only, never backed up or shown, and removed by deleting its line.
- With a web coach, also write `cloud_max_chars = 30000` in the profile's settings (a 40-minute workout with room for retakes: about $0.45 on Fish Audio, $0.75 on Inworld, $2.40 on ElevenLabs): tell them the figure and that a build over it stops before sending.

**Keys.** `./sweatcast keys` prints "set" or "not set" for each web service, never a key. With none set and a web coach wanted, recommend **Fish Audio** for a first key (no minimum, among the cheapest, the simplest sign-up) and walk them through it in short numbered steps: sign up at https://fish.audio, add a few dollars of credit under billing, then make a key at https://fish.audio/app/api-keys (Create New Key; copy it, since it may not be shown again). Mention the others in one line as more choices, each with its key page; more keys mean more voices to choose from in an audition:
- **Fish Audio** (https://fish.audio/app/api-keys): prepaid credit, no minimum; about $0.30 a workout, among the cheapest.
- **ElevenLabs** (https://elevenlabs.io/app/settings/api-keys): the Free account works within its 3 custom voices and its monthly allowance (about half a workout), with prepaid pay-as-you-go usage ($5 minimum) beyond it; about $1.60 a workout on the natural model, $0.80 on the faster one. Not yet tried on a Free account: say so. The key needs two permissions when it's made: Text to Speech, and Voices: write.
- **Gemini** (https://aistudio.google.com/apikey): a key from Google AI Studio (not Google Cloud), with prepaid credit ($5 minimum); about $0.27 a workout until the end of 2026, about $0.54 from 2027. Its free tier uses requests for training with human review, its terms say it's not for consumer use, and it's for adults (18+): say so.
- **Inworld** (https://platform.inworld.ai, Settings > API Keys): the On-Demand plan, $0 a month with prepaid credit ($10 minimum); about $0.50 a workout.

Then add the key:
- **On their computer** (a terminal, VS Code or the desktop app): `./sweatcast keys init <service>` (fish, elevenlabs, gemini or inworld) adds an empty line to `me/.env`, and `./sweatcast keys open` opens that file in the computer's own text editor. They paste the key after the `=` and save (say exactly that: "paste it right after the = sign, with no spaces, then save and close"). Never ask for the key in the chat, and never open, print or copy `me/.env` yourself. `./sweatcast keys` confirms it's set.

**Delivery.** Where finished MP3s should go: a folder that syncs to their phone (iCloud Drive is `~/Library/Mobile Documents/com~apple~CloudDocs/<folder>`, Google Drive for desktop is `~/Library/CloudStorage/GoogleDrive-*/My Drive/<folder>` on a Mac and usually `G:/My Drive/<folder>` on Windows (forward slashes), Dropbox is `~/Library/CloudStorage/Dropbox/<folder>`), or nowhere, keeping them in each workout's folder in `me/workouts/`. Say that once a build's copy lands there, the local MP3 is removed and only the script's text stays, so this folder is where the audio lives. Check the folder exists with `ls`, and offer to create the subfolder. It is the profile's `deliver_to` setting, a folder or a list of them, one per computer the listener renders on (each build copies to the ones that exist there); a request to change where workouts go runs this part alone.

**Writing the files.**
- `me/profile.md` and `me/health.md`: fill in the placeholders the answers cover (the template is `me.example/`), and delete lines the user has nothing for (the quick start leaves the rest for later). Keep the `+++` block at the top of each file. In `me/profile.md` that block is TOML and holds every setting the tools read: `name`, `setup`, `experience`, `likes`, `dislikes`, `deliver_to`, `words_per_minute`, `youtube_favorites` and `puzzles` (@handles without the @), `render` (the local engines, in order) and, with a web coach, `cloud_max_chars`, one `[[kits]]` table per kit (`name`, `equipment`, and for free weights `weights` and `unit`), and one `[[feeds]]` table per feed (`label`, `kind`, `value`). Edit those values in place; the prose below the block is for Claude only.
- **Feeds** (finish setting me up). Weather: the neighborhood's latitude and longitude, rounded to two decimals. Teams: find each team's ESPN path (the `sport/league/team` part of its ESPN team page URL, such as `hockey/nhl/nj` or `soccer/usa.1/10739`) with a web search. Local news: one or two outlets' RSS feeds for the city. Keep the shipped science and puzzle feeds unless the user doesn't want them. YouTube handles: check each one resolves (`https://www.youtube.com/@<handle>`).
- Then run `./sweatcast check`. It lists every line still showing the template's `[hint]`, any feed not filled in, a missing experience level, likes or dislikes the catalog doesn't know, kit equipment not in the catalog, a malformed `[[limits]]` row (which would apply no limit at all), an unknown rehab id or one that isn't a rehab movement, a bad `flags` value, an injury written in prose with no `[[limits]]` row, and anything the tools can't read, with line numbers; fix each issue until there are none (notes, such as no delivery folder, the stand-in coaches, a default web coach made the first time it's used, or what the quick start left for later, are fine). After filling in feeds, run `./sweatcast feeds` once, fix or remove any source it lists under "Couldn't fetch", and run it again.

## Step 4: the local engine, when the route includes local

If doctor (or `./sweatcast models adopt --dry-run`) found sweatcast's models already downloaded elsewhere, offer to move them (`./sweatcast models adopt`) rather than download again. Say the size (3.3 GB for Chatterbox Turbo on a Mac, 4 GB on Windows or Linux, plus the engine itself), then run `./sweatcast setup --local` with `run_in_background: true`. It skips what's done. On a processor-only computer, the smoke test (`./sweatcast build knowledge/smoke-test.draft.txt "smoke-test"`) measures this computer's render speed, and doctor then quotes the time a 30-minute workout takes; past an hour, suggest a web coach and let them choose.

## Keep it safe

- Ask whether they have a GitHub account. Without one, say `me/` stays on this computer and everything works; to keep a copy, they can copy the `me` folder now and then to somewhere private (it holds their health notes). With one, suggest backing up `me/` as its own private git repo: `git init` inside `me/`, commit, and push to a private remote (`gh repo create sweatcast-me --private --source . --push`). The engine's git ignores `me/`, so the two never mix, and the pre-push hook blocks `me/` from the public repo.
- Summarize what was written, in a few lines, and where to change it later ("ask me to update your profile").
